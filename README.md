# Umbrella Parade Kindle 出版ナビ

Kindle 本の企画・執筆・表紙・KDP 登録・カテゴリー選定・告知・原稿準備を、1 つのプロジェクトで管理するブラウザツールです。

公開版: https://umbrellaparade.github.io/Kindle-Publishing-Navi/

## 主な機能

- 初めての方が「本を作る→発売日を逆算→フェーズ0→バックアップ」の順で始められるサイト内マニュアル
- ゴリアスさんのBrain教材を新しいタブで開き、教材や自分が確認できるGPTをCodexスキルへ整理する安全な指示文を1クリックでコピーできる「ゴリアスさんのBrain＆スキル化」
- ゴリアスさんの「AI出版自走キット」の出版フロー30項目・備考15件を内容面で連携し、一般向けに補完したチェックリスト
- 発売目標日から標準 8 週間の工程日を逆算
- 自動設定後の個別日付変更と、手動日を守った再計算
- 制作・KDP 登録・プロモーションのチェックリスト（全体表示／フェーズ別表示）
- KDP 書籍説明文の専用タブ、HTML 整形、文字数・禁止要素チェック
- 表紙と Amazon A+ コンテンツの一括管理、A+ 画像の自動軽量化
- プロモーションメモごとの関連ドキュメントリンクと折りたたみ
- スクロール中も画面上部に残るメイン機能タブ
- 書籍情報や下書きをまとめた「Codex 相談文」のコピー
- 本の種類で絞り込めるカテゴリー候補管理
- Google ドキュメントでの見出し・目次・改ページと、DOCX / EPUB の原稿作成ガイド
- 完成原稿をKindle向けDOCX、しまうま出版向けA5・A6印刷用PDFへ仕上げ、QRコード付きカードも本文へ配置できる「Kindle原稿整形ツール（テスト版）」へのPC専用案内と全21章の利用マニュアル
- 出版後の改訂・続編・音声・紙書籍・コンテンツ展開を残す専用メモ
- 辛口論評の前提5項目保存、原稿末尾の読込確認、指摘4分類、履歴・点数比較・修正タスク化
- 辛口論評に使うGPT会話を `CRITIQUE-001` から世代管理し、対象原稿版・論評回・引継ぎ先を論評履歴とは分けて残せる「辛口論評GPT 管理」
- 本ごとの企画・市場調査サマリー・章構成・一問ずつの取材・執筆指示書版・意思決定・Kindle出版サポートGPTの世代を保存し、目次を「仮目次（編集中）」「確定目次（現在使う読み取り専用版）」「過去の目次履歴」に分けられる「企画・取材・構成ノート」
- 長くなって重くなったGPT会話を新しいセッションへ移すとき、GPT-001からの連番、使用中／引継ぎ済み、引継ぎ先と短い引継ぎメモを管理できる「Kindle出版サポートGPT 管理」
- Kindle出版サポートGPTと辛口論評GPTの両方で、編集可能なひな形から「前のGPTに引継ぎ書を作ってもらう文」と「新しいGPTへ最初に貼る文」を分けてコピー
- 目次タイトルとは別に「第N部／第N章／第N話／第N節」を現在の種類と並び順から自動表示し、並べ替えや種類変更にも追従
- 現在の仮目次にある同じ種類を、プレビュー後に「章から話」などへ安全に一括変更
- Codexから返された目次Markdownをプレビューして新しい仮目次へ一括切替でき、旧目次・承認・取材リンク・確定目次・履歴を削除しない「目次を書き直す」機能
- 仮目次と現在の確定目次の各項目で、カードを折りたたんだままでも原稿を書き終えたかをチェックし、章ごとの原稿保存先をすぐ開ける原稿進捗管理
- 章へ紐づけた執筆用質問を仮目次・現在の確定目次から直接確認し、質問本文だけを1クリックでコピー
- 対応形式の市場調査正本Markdownを、既存データとの差分プレビュー後に安全に追加
- プロジェクト・原稿・画像をまとめたバックアップ／復元
- 旧 Pages 版からのプロジェクトコピー移行
- 新版を検出したときの「更新する／あとで」通知

## データ保存について

GitHub Pages 版は `VITE_STORAGE_MODE=local` で動作し、プロジェクトはブラウザの localStorage、画像は IndexedDB に保存します。同じ URL・ブラウザでアプリを更新しても、通常はデータを維持します。旧版の原稿調整データとルビ辞書も削除せず、バックアップ対象として保持します。

「企画・取材・構成ノート」の保存形式、共有用書き出し、バックアップ競合、容量上限は [データ仕様](docs/planning-notes-data-spec.md) を参照してください。

「Kindle出版サポートGPT 管理」は、当面の母艦であるGoogleスプレッドシートの「Kindle出版サポートGPT」タブと併用できるよう、 **GPT管理ID／企画・作品名／セッション名／Kindle出版サポートGPT URL／担当範囲／状態／開始日／引継ぎ先ID／引継ぎメモ／備考** の列順にそろえています。Googleスプレッドシートとは自動同期しないため、必要な行だけ確認して転記してください。

Kindle出版サポートGPT管理・辛口論評GPT管理・両方の引継ぎテンプレートは、同じブラウザ内と **完全バックアップ** にだけ保持します。第三者へ渡す共有用JSON／Markdownからは管理記録とテンプレート全体を除外します。独立した「プロジェクトパック」はなく、既存の企画ノート共有用JSON／Markdownが共有経路です。完全バックアップは共有ファイルではありません。登録したGPTの会話URLは各管理画面の専用 **GPT URL欄だけ** に保存でき、共有や引継ぎ文へは出ません。限定URL・会話URL・署名付きURL、会話ID・セッションID、APIキー、パスワード、生の非公開会話は引継ぎ文へ自動挿入せず、引継ぎメモ・備考・テンプレートにも貼り付けないでください。一般公開URLは必要な場合だけ内容を確認して利用します。

目次はいきなり確定せず、まず仮目次で部・章・話・節を編集できます。途中案は仮目次メモとして履歴へ残せます。仮目次を確定版として明示保存すると、その時点の構成が読み取り専用の確定目次になり、以前の確定版も履歴へ残ります。目次全体の仮／確定は各項目の「案／要確認／本人承認済み／採用しない」とは別の管理です。旧版から引き継いだ目次はID・内容・階層・順番を保った仮目次となり、利用者が操作するまで勝手に確定しません。

各カードでは、たとえば **「第1章」** という自動番号と **「諦めることは、負けることなんだろうか。」** というタイトル（題名）を分けて表示します。「題名」欄には見出し本文だけを入力すればよく、並べ替えると第1章・第2章などの番号が現在の順番へ自動で変わります。種類を章から話へ変えた場合も「第N話」へ自動で切り替わります。番号は同じ親の中で種類ごとに数えるため、別の部へ入れた話は第1話から始まります。変わるのは表示番号で、保存済みのタイトル、構成項目ID、階層、取材・指示書との紐づき、承認状態、原稿進捗などは失われません。

同じ種類の項目が多い場合は、仮目次の **「種類をまとめて変更」** から、現在の種類と変更後の種類を選べます。保存前の **「変更内容を確認」** で対象件数と停止理由を確認し、明示的に実行したときだけ現在の仮目次を変更します。確定目次、過去の目次、採用しない項目は変更しません。対象種類に本人承認済みが含まれる場合や、階層の関係で変更できない項目が1件でも見つかった場合は全体を停止し、一部だけを変更しません。変更対象でも、構成項目ID、タイトル、順番、階層、取材・指示書との紐づき、承認状態、原稿進捗、原稿リンクは保ちます。

仮目次・現在の確定目次・過去の目次では、部・章・話・節ごとに詳細を折りたためます。タイトル、種類、状態を残し、説明、編集操作、原稿メモ本文を閉じます。仮目次と現在の確定目次では、折りたたんだまま原稿完成チェックと **「原稿を開く／原稿リンクを設定・変更」** を使えます。さらに **「すべて折りたたむ／すべて開く」** で、今選択している目次だけをまとめて開閉できます。開閉状態は同じ端末のブラウザ内へプロジェクト別に保存し、目次本文、完全バックアップ、共有JSON／Markdownには含めません。

仮目次を大きく作り直すときは、一つずつ削除したり、取材との紐づきを外したりする必要はありません。「目次を書き直す」でCodexの目次Markdownを貼り付けるか、空の仮目次から始め、差し替わる内容を確認してから一括切替できます。旧目次の項目とそれに紐づく取材・承認済み記録は、旧目次参照としてIDを保ったまま残ります。現在の確定目次と過去の目次履歴も変わらず、新しい仮目次は利用者が改めて確定操作をするまで確定目次になりません。

仮目次と現在の確定目次では、部・章・話・節ごとに **「原稿を書き終えた」** をチェックでき、Googleドキュメント、Notion、OneDrive、Dropboxなどの原稿URLを登録して直接開けます。カードを折りたたんだ状態でも、見出しに残る **「原稿：未完成／完成」** のチェックと **「原稿を開く／原稿リンクを設定・変更」** を使えます。このチェックは目次や各項目の承認とは別の執筆進捗です。確定目次の本文は読み取り専用のままですが、原稿進捗とリンクは更新できます。過去の目次履歴は当時の記録を守るため読み取り専用です。外部サービスの本文を同期・読取・編集する機能ではありません。

各項目には **原稿メモ** を追加できます。タイトルと本文を自由に入力できるため、質問から執筆する本だけでなく、書き出し案、使う体験、参考資料、注意点などにも利用できます。以前から章へ紐づけて保存していた質問は削除・移動せず、同じタイトル、本文、版、紐づきを保ったまま原稿メモとして表示します。原稿メモは共有用JSON／Markdownにも含まれるため、非公開情報や認証情報は保存しないでください。

Googleドキュメントで原稿を書く場合は、このナビの執筆用目安としてページ形式の用紙サイズをA5（14.8×21.0cm）にしておくと、本らしいページ感覚でKindle向け原稿の分量や改ページを確認しやすく、後からA5判の紙の本へ展開するときの下準備にも便利です。これはKDP電子書籍の指定ではなく、通常のKindle電子書籍はA5固定表示になりません。電子版はKindle Previewerで確認し、紙版は入稿先の判型・余白・裁ち落とし仕様へ別途調整してください。

別端末・別ブラウザへの移動、ブラウザのサイトデータ削除、ドメイン変更には引き継がれません。画面上部の「データ管理」から定期的にバックアップしてください。バックアップにはナビ内のプロジェクト・メモ・保存画像・旧版で保存した原稿データが含まれます。章ごとの原稿URL、Kindle出版サポートGPT管理、辛口論評GPT管理、編集した引継ぎテンプレートは完全バックアップへ含まれますが、外部サービスの原稿本文、DOCX、EPUB等のファイル本体や、AI接続設定として保存されたAPIキー・トークンの専用保存キーは含めません。原稿URL、2つのGPT管理、引継ぎテンプレートは共有用JSON／Markdownから除外します。ただし、原稿やメモへ手作業で貼り付けた機密文字列・非公開取材は通常バックアップに含まれるため、共有用ファイルとは分けて安全に保管してください。

複数タブからの同時書き込みは可能な範囲で直列化していますが、編集中の画面状態まで完全には同期されません。同じプロジェクトは 1 タブで編集してください。

## ゴリアスさんの教材との関係

このツールは、ゴリアスさんの「AI出版自走キット」のスプレッドシートにある出版工程と備考の要点を、ブラウザ上のチェックリストと「手順のポイント」に取り込んだ補完ツールです。発売日からの日程逆算、KDP 登録、カテゴリー、説明文、表紙・A+、原稿作成、プロモーション、辛口論評など、Kindle 出版で迷いやすい部分の説明と管理機能を追加しています。

Google スプレッドシートとのリアルタイム同期ではありません。シート側の入力はこのツールへ自動反映されず、このツールの入力もシートへ書き戻されません。教材の音声・Gem・配布リンクは教材側から開き、このツールでは進捗、目標日、候補、メモを管理します。

「ゴリアスさんのBrain＆スキル化」では、Brain教材の商品ページを新しいタブで開けます。スキル化は、画面内の指示文をコピーして新しいCodexのチャットへ貼り、教材・GPTの用途、保存先、必要な分け方をCodexと確認してから進めます。GPTのURLだけでは非公開の指示や知識ファイルは読み取れないため、自分が確認・利用できる指示、会話スターター、知識ファイルを用意してください。限定URL、ログイン情報、Cookie、APIキーはスキルへ保存せず、教材本文をそのまま転載しません。

## 辛口論評を安全に進める

「辛口論評」では、評価前に「誰に向けた本か」「何を伝える本か」「読後にどう変わってほしいか」「予定している価格」「出版の目的」の5項目を本ごとに保存できます。Codexへの相談文は、まず原稿の「最終章のタイトル」と「最後の一文」を答えてもらい、最後まで読み取れていることを確認してから論評へ進む構成です。

返ってきた指摘は「必ず直す」「読者確認」「著者判断」「見送る」の4種類へ整理し、優先度の高い1〜3件ずつ修正します。修正前の原稿を残し、悪くなった場合は前の原稿へ戻せます。高得点を取ることではなく、読者へ伝わる本にすることが目的です。相談文はクリップボードへコピーするだけで、外部へ自動送信しません。

「辛口論評GPT 管理」は、論評結果・履歴・著者判断とは別の会話台帳です。使用中は1件だけにし、次の会話を保留で登録して受領確認後に切り替えます。切り替えても論評結果を採用済みにしたり、原稿・目次・著者判断を上書きしたりしません。最終判断はこれまでどおり著者が行います。

## SNS 投稿文をコピーする

「プロモーション戦略メモ」の各SNS投稿欄にある「投稿文だけコピー」を押すと、タイトルや選択SNSを含めず投稿本文だけをクリップボードへコピーできます。左の戦略メモ欄は「戦略メモだけコピー」でメモ本文だけをコピーできます。コピーだけではSNSへ公開されません。

より継続的に使う場合は、[`codex-skills/kindle-sns-promotion-advisor`](codex-skills/kindle-sns-promotion-advisor) を Codex の skills フォルダへコピーしてください。Windows の標準的な保存先は `%USERPROFILE%\.codex\skills\kindle-sns-promotion-advisor` です。専用スキルは投稿案・リライト・公開前チェックに対応し、内部の資料名や手法名を公開文へ出さない設計です。

## リリース手順

1. `package.json` と `package-lock.json` の version を同じ SemVer に更新する。
2. `public/version.json` の version を同じ値に更新する（CI が一致を検証し、ビルドへ反映します）。
3. `src/hooks/useAppUpdate.js` の `FALLBACK_APP_VERSION` と `tests/appUpdate.test.js` の固定期待値も同じ値に更新する。
4. テスト、lint、build を通して `main` へマージする。
5. GitHub Actions の `Deploy GitHub Pages` 完了後、公開画面を確認する。

すでに開いている利用者の画面は `version.json` を定期確認し、新版があれば選択式で通知します。Service Worker は使っていないため、新しく開いた画面や通常の再読み込みでは最新版が配信されます。
